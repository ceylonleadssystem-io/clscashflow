# Ceylonry POS: release notes, 2026-11-23

## Features

### 1. Live support session (#179)
Support can now help a client live, with nothing to install. The client reads out a one-time code, support joins from the admin portal, sees the client's POS page, and guides them on their own screen.

**How it works**
- The client's POS and the support agent's browser connect directly. It works on tablets too.
- The code is 6 digits, works once and expires after 10 minutes.
- Typed text, PINs and passwords are hidden from support. Sign-in and PIN screens are not shown in the live view.
- Support can draw on the client's screen (Pointer, Highlighter, Pen, Arrow, Spotlight, Note) and ask to open a POS screen for the client.
- Support can click, type and scroll inside the POS only if the client allows it. Sign-in, PIN, payment and delete actions always stay with the client.
- If the connection drops, it reconnects by itself for up to 2 minutes. Control has to be allowed again afterwards.
- A connection line shows "Direct" or "Through the relay" with the delay in ms, and "Slow" above 500 ms.
- For networks that block direct connections, a relay server can be switched on (setup in `docs/support-live-session.md`). Without it, direct connections only.

**Client: start a session**
1. Open *Settings > Plan & Support*
2. In *Live support*, click *Get support code*
3. Read the 6 digits to Ceylonry Support (valid once, expires in 10 minutes)
4. A banner shows "Ceylonry Support can see this screen." Click *End session* at any time to stop

**Client: when support asks for something**
1. "Support asks to open ..." : click *Open it* or *Not now*
2. "Support asks to click and type for you ...": click *Allow* or *Not now*
3. While control is on, click *Pause control* to take it back

**Support: join and guide**
1. Sign in to the admin portal and open *Live support*
2. Enter the *6-digit code* and click *Join*
3. Pick a tool (*Pointer*, *Highlighter*, *Pen*, *Arrow*, *Spotlight*, *Note*), a colour, and draw on the live view. *Clear* removes the drawings
4. To send the client somewhere, choose *Take the client to...* and click *Send*
5. To control the page, click *Ask to control*. Once the client allows it, use the *Control* tool; *Release* hands it back

### 2. Support-only admin accounts
Admin accounts now have a type. A *support* account can use Live support and nothing else; the server refuses every other portal function for it. Accounts with no type stay full admins, so existing accounts need no change.
- Create one with `node scripts/setup-admin-db.mjs` (once, adds the type field) then `node scripts/hash-admin-password.mjs` and answer "support" to "Account type".

## Fixes
- Settings pages (System Options, Users, Menu Admin, Device Manager) now scroll with the mouse wheel and touch in full-screen mode (BUG 0019 follow-up).

## Other
- Admin portal: the "Open client's POS" and "Sign in as client (live)" buttons were removed. Live support replaces both, and the server no longer issues a client sign-in token.
- The admin account script writes the account type only when one is chosen, so it works on a database without the type field.
- New setup and test guide: `docs/support-live-session.md`.

*Not verified:* no browser or tablet testing was done as part of this write-up; the relay server is not live until configured.
